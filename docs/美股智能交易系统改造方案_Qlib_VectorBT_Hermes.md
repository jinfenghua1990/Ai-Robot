# 美股智能交易系统改造方案（基于 Qlib + VectorBT + Hermes）

> 版本：V1.0 ｜ 日期：2026-07-31
> 目标：不重复造轮子，用成熟开源量化引擎做底层"数据/因子/扫描/回测"，
> 保留 AIROBOT 已做好的"发现机会 → 评分 → 解释 → 给计划"的 AI 层（Hermes）。

---

## 0. 原则（先对齐，避免走偏）

1. **Dashboard 不重建。** AIROBOT 的 React 前端 + FastAPI 后端是"展示与交互层"，已是成熟产品形态，**绝不**用 LEAN / Qlib 自带 UI 替换它。
2. **引擎是"能力插件"，不是"系统"。** 每个开源项目只取它最强的一段（因子、扫描、回测、实盘），嵌进我们自己的服务边界。
3. **真实数据优先，估算兜底。** 沿用已落地的腾讯 gtimg 实时源；Qlib/VectorBT 需要的历史数据单独建仓，缺失时回退现有估算逻辑。
4. **渐进式，先见效再扩张。** 先做能立刻提升现有评分/扫描质量的（Qlib 因子 + VectorBT 扫描），实盘（LEAN）留到最后一阶段。
5. **所有新增引擎跑在独立 Python 环境**，不污染现有 9000 后端（系统 Python 3.9）的依赖。

## 1. 候选项目现实评估（已用检索校准，非凭印象）

| 项目 | 真实规模/状态 | 最强能力 | 对 AIROBOT 的价值 | 风险 / 不适合 |
|---|---|---|---|---|
| **Microsoft Qlib** | ~4.4–4.6 万★、MIT、仍维护（2026 有提交、33+ 贡献者） | 因子表达式(Alpha158/360)、ML 模型、回测、组合优化；RD-Agent 自动挖因子 | **美股评分引擎的"因子+ML"内核**，替换我们手写的 `marketScore.js` 估算 | 学习曲线陡；**数据准备是最大门槛**（需 qlib 二进制格式）；A 股比美股成熟；发布慢、issue 多 |
| **VectorBT** | ~5–6 千★、Python、开源核心有限（PRO 商业） | 向量化高速回测/扫描，5000 只美股同时算 MA/RSI/MACD/突破 | **股票扫描器**，直接接我们"策略扫描"页 | 开源版功能受限、无实盘；需要历史数据 |
| **Backtrader** | ~1.2 万★+、成熟、文档多 | 事件驱动回测，策略易写 | 验证我们的"青龙趋势/白虎突破/回踩"策略（离线回测） | 偏研究，无 ML、无实盘 |
| **QuantConnect LEAN** | ~1–1.1 万★、C#/.NET、生产级 | 多资产实盘（IBKR 等）、完整交易生命周期 | 未来**实盘执行核心**（如需自动下单） | C# 技术栈重；需券商账户；**当前阶段不必要** |
| **FinRL** | ~1 万★、研究级 | 强化学习交易决策 | AI 学习模块（可选） | 研究性质，非生产；**不作为主系统** |
| **NautilusTrader** | 高热度、生产级、高频 | 高频/实盘多资产 | 暂不需要（我们不做高频） | 过度工程 |

**结论（修正原 proposal 的过度乐观）：**
- ✅ **Qlib + VectorBT 立刻有用**，直接增强现有"评分 + 扫描"。
- ⚠️ **Backtrader 作为离线回测校验**，不进生产。
- ❌ **LEAN / FinRL / Nautilus 现阶段不落地**，只在架构图里留接口位，避免范围爆炸。

## 2. AIROBOT 现状对齐（我们已有什么，避免重复）

- 端口 9000：React(Vite) 前端 + FastAPI(Python 3.9) 后端。
- 已建成：**港股研究中心 / 美股智能交易系统**（顶部菜单直达），含评分、策略、市场环境、仓位管理标签页。
- 已接入真实数据：`/api/global-market/fundamentals/{HK|US}`（腾讯 gtimg 实时 PE/PB/股息/估值分位）。
- 评分模型：前端 `marketScore.js` 手写的 100 分权重模型（港股 基本面30/资金25/估值20/趋势15/催化10；美股 趋势30/基本面25/资金20/动量15/风险10）。
- **缺口**：无因子研究、无历史回测、无 ML 排序、扫描慢（逐只 Yahoo 拉取）。

→ Qlib 补"因子+ML 排序+回测"，VectorBT 补"高速扫描"，正好对应缺口。

## 3. 推荐集成架构

```
┌──────────────────────────────────────────────────────────┐
│  浏览器 (React Dashboard @9000)  ← 展示/交互层，不重建       │
│  港股中心 / 美股中心 / V2 多因子 / A股                       │
└───────────────────────┬──────────────────────────────────┘
                         │  REST /api/quant/*
┌────────────────────────▼─────────────────────────────────┐
│  FastAPI 主服务 @9000 (Python 3.9，系统)   ← 现有，不动      │
│  路由聚合层：把下游引擎结果组装成前端卡片                       │
└──────┬───────────────────────────┬─────────────────────────┘
       │ 子进程/HTTP                │ 子进程/HTTP
┌──────▼─────────────┐    ┌────────▼──────────────────────┐
│ Quant Service       │    │ Scan Service                  │
│ (Python 3.10 venv)  │    │ (Python 3.10 venv)            │
│  Qlib: 因子+ML 排序  │    │  VectorBT: 高速扫描/回测        │
│  + 历史数据仓        │    │  + 技术信号                    │
└──────┬─────────────┘    └────────┬──────────────────────┘
       │                            │
┌──────▼────────────────────────────▼─────────────────────┐
│  数据层                                                   │
│  实时：腾讯 gtimg（已用）  历史：Qlib 二进制仓 / CSV 派生    │
└──────────────────────────────────────────────────────────┘

        Hermes AI Agent（现有 AI 层）
              │ 读取上面任一层的输出，生成

```

**关键点**：新增两个 Python 微服务（独立 venv，避免污染 9000），由主 FastAPI 通过本地 HTTP 或子进程调用，结果组装成前端卡片。前端零重构，只新增数据字段。

## 4. 分层映射（每个引擎只取最强一段）

| AIROBOT 层 | 现状 | 改造后 |
|---|---|---|
| 数据层 | 腾讯 gtimg 实时 | + Qlib 历史因子仓（日频） |
| 因子/ML 层 | 手写估算 | **Qlib Alpha 因子 + LightGBM/Transformer 排序** |
| 扫描层 | 逐只 Yahoo（慢） | **VectorBT 向量化批量扫描** |
| 评分层 | `marketScore.js` 权重 | 权重模型保留为"可解释外壳"，内核换成 Qlib 输出 |
| 回测层 | 无 | **Backtrader 离线校验**策略（不改生产） |
| 解释/计划层 | Hermes | 不变，消费新数据 |
| 实盘层 | 无 | 架构预留 LEAN 接口（不实现） |

## 5. 分阶段路线图

### Phase 0 — 数据地基（必须先做，否则 Qlib/VectorBT 都跑不起来）
- 在独立 venv（Python 3.10）装 `pyqlib`，`brew install libomp`（Apple Silicon 必需）。
- 拉取美股日频数据（社区数据集 chenditc/investment_data，或 Yahoo 批量）转 Qlib 二进制格式到 `~/.qlib/us/`。
- 产出：可查询的美股历史因子仓。**这是 Qlib 上手最大门槛，单独排期。**

### Phase 1 — Qlib 评分内核（替换手写估算的"硬"部分）
- 用 Qlib 在美股上跑 Alpha158 因子 + 一个基线模型（LightGBM），输出**个股排序分数**。
- 封装 `Quant Service`：REST `POST /api/quant/score {market:'US', codes:[...]}` → 返回 Qlib 排序分 + 关键因子值。
- 主 FastAPI 聚合：Qlib 排序分 × 我们权重外壳 → 前端"美股评分"页展示真实 ML 排序（保留"趋势/动量/风险"等可解释维度）。
- **不删** `marketScore.js`：Qlib 取不到时回退估算，保证页面永不空白。

### Phase 2 — VectorBT 扫描器（提速 + 扩策略）
- VectorBT 批量计算美股 MA/RSI/MACD/突破，输出"青龙趋势/白虎突破/回踩"信号命中列表。
- 封装 `Scan Service`：`GET /api/quant/scan?strategy=longqing` → 命中股票数组。
- 前端"策略扫描"页改调此接口，扫描从分钟级降到秒级、覆盖全美股。

### Phase 3 — Backtrader 离线回测（校验，不进生产）
- 把 Phase 2 命中的策略用 Backtrader 跑历史回测，输出夏普/最大回撤/胜率。
- 仅作为"策略可信度"标注展示在策略页，**不参与实时信号**。

### Phase 4 — 实盘接口预留（可选，最后）
- 仅定义 `LEAN` 适配层接口与配置位；**不接券商、不自动下单**，除非你明确要实盘。

## 6. 关键风险与"不要做"清单

- ❌ **不要**用 LEAN/Qlib 的 UI 替换 React dashboard。
- ❌ **不要**在 9000 主服务里直接 `import qlib`（依赖冲突 + Python 版本不匹配），必须独立 venv + 子进程/HTTP。
- ❌ **不要**期望 Qlib 开箱即用美股——数据准备是数天级工程，Phase 0 单独排期。
- ❌ **不要**现在做实盘自动交易（LEAN + 券商），风险与合规成本高，留接口即可。
- ⚠️ Qlib 美股数据质量不如 A 股，排序结果需人工抽样校验后再信任。
- ⚠️ VectorBT 开源版功能有限，若需高级特征再评估 PRO 或自研向量化。
- ⚠️ "Hermes AI Agent" 按你的 AI 层理解；本文假设它消费上述任意层输出生成解释，**其内部结构需你确认**。

## 7. 下一步建议（最小可落地起点）

**先做 Phase 0 + Phase 1 的脚手架**，验证 Qlib 能在你的机器跑通美股排序，再决定是否全面推进：

1. 建 `backend/quant/` 独立服务骨架（Python 3.10 venv + FastAPI 壳 + 健康检查）。
2. 跑通 Qlib 数据准备（美股日频 → 二进制）。
3. 输出第一版 `POST /api/quant/score` 并接到前端"美股评分"页做 A/B（真实 ML 排序 vs 现有估算）。
